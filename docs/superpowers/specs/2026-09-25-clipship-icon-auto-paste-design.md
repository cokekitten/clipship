# Clipship: Fileport Icon Set + Auto-Paste + Tray Fixes

Date: 2026-09-25
Scope: replace the framework-default Tauri icon with a purpose-designed SVG icon set
(badge + macOS menu-bar template glyph), add an opt-in "paste after upload" behavior for
the global shortcut, and fix tray presentation (Windows hover tooltip, macOS
theme-adaptive monochrome tray icon).

## Goals

1. **Icon** — ship the chosen "Fileport" design everywhere the framework default appears
   today: bundle icons (icns/ico/pngs), tray, dev favicon, settings-window logo.
2. **Auto-paste toggle** — off by default (current behavior unchanged). When on, after the
   global shortcut uploads and the path is written to the clipboard, Clipship simulates a
   paste keystroke so the path lands in the frontmost app without a manual Cmd/Ctrl+V.
3. **Tray fixes** — hovering the tray icon shows `Clipship` (currently an empty tooltip
   box on Windows); on macOS the tray icon is solid monochrome and follows the menu-bar
   theme (black on light, white on dark).

## Non-goals

- Auto-paste for non-shortcut triggers (tray menu `Upload clipboard now`, settings UI).
  When the settings window is focused, a synthetic paste would land in Clipship itself.
- Separate hand-switched black/white tray assets. macOS template images already render
  black/white per menu-bar appearance (see Decisions).
- Custom monochrome tray glyph for Windows/Linux (they keep the color badge).
- Localization, dark mode for the settings window, animated icons.

## Decisions (as agreed with the user)

- **Auto-paste is gated on the global shortcut path only** (see Non-goals for why the
  settings UI is excluded).
- **Auto-paste fires only when the path actually reached the clipboard**
  (`UploadSuccess.clipboard_updated == true`). In SSH mode the user may copy something
  else mid-upload; in that case Clipship must not paste whatever the user copied — the
  existing `UploadSucceededButClipboardChanged` notification already explains the state.
- **macOS menu bar uses a template image** (system renders it black or white per theme)
  rather than shipping two assets and tracking appearance manually. This is exactly the
  requested "solid color, black/white versions that adapt to the theme".

## 1. Icon

### 1.1 Assets

| File | Role |
|------|------|
| `public/app-icon.svg` | Source of truth for the badge. 1024×1024 viewBox, rounded square (`rx=229`), deep-pine → lime gradient, folded-file + `>_` mark. Checked in. |
| `public/tray-glyph.svg` | Source of truth for the menu-bar glyph. 24×24 viewBox, solid `#000` on transparent (template input). Checked in. |
| `src-tauri/icons/*` | Generated by `pnpm tauri icon public/app-icon.svg` — replaces every framework-default file in place (same filenames, so `tauri.conf.json`'s icon list is unchanged). Platform subfolders the CLI also emits (android/ios) are deleted; the bundle targets are dmg/msi/nsis only. |
| `src-tauri/icons/tray-template.png` | 44×44 black-on-transparent PNG rendered from `public/tray-glyph.svg` (22pt@2x menu-bar size). Generated once with a documented one-liner (headless Chrome screenshot with a transparent background) and checked in. |

Both SVGs are checked in under `public/` so the web side can reference the badge by URL;
the glyph lives beside it as the single icon source folder.

### 1.2 Presentation

- **Bundle / Dock / taskbar**: the generated `src-tauri/icons/*` (replaces the Tauri
  default logo). Verified by rebuilding the bundle.
- **Tray, macOS**: embed `tray-template.png` (`tauri::image::Image::from_bytes(include_bytes!(...))`)
  and build the tray with `icon_as_template(true)` (tauri v2 tray API). The system then
  renders the glyph black/white per menu-bar appearance.
- **Tray, Windows/Linux**: keep `app.default_window_icon()` (the color badge), as today.
- **Tooltip**: `TrayIconBuilder::tooltip("Clipship")` on all platforms — fixes the empty
  hover box on Windows; harmless where the platform ignores tooltips.
- **Dev favicon**: `index.html` gets `<link rel="icon" type="image/svg+xml" href="/app-icon.svg" />`.
- **Settings window**: `App.svelte` header shows `/app-icon.svg` at 24px next to the
  "Clipship" title.

## 2. Auto-paste

### 2.1 Config

- New field `auto_paste: bool` on `Config` (`src-tauri/src/config/mod.rs`), `#[serde(default)]`,
  `false` in `Default`. Config version stays 1 — an absent field means off, same migration
  pattern as `shortcut_double_tap` and `auto_cleanup`.
- `save_general_config` copies `auto_paste` alongside `mode` / `shortcut` / `shortcut_double_tap` /
  `auto_cleanup`. `save_config` / `save_ssh_config` already persist the whole struct.
- Frontend `src/lib/types.ts` gains `auto_paste: boolean`; `App.svelte`'s initial state
  sets it to `false`.

### 2.2 UI

In `ShortcutSection.svelte`, a third row (same Label + Switch pattern as the double-tap
row):

- Label: **Paste path after upload**
- Description: *After the shortcut uploads, paste the path into the frontmost app
  automatically. Only applies to the global shortcut. macOS requires the Accessibility
  permission.*

The existing `$effect` auto-save persists the toggle (300 ms debounce), no extra wiring.

### 2.3 Behavior

- New module `src-tauri/src/paste/mod.rs`:
  - `pub fn should_paste(cfg: &Config, result: &Result<UploadSuccess, UploadError>) -> bool`
    — pure decision: true only when `cfg.auto_paste` **and** the result is
    `Ok(UploadSuccess { clipboard_updated: true, .. })`. Unit-tested.
  - `pub async fn paste_after_delay()` — sleeps ~100 ms (lets the hotkey's own key-up
    events settle), then calls `send_paste()`.
  - `fn send_paste() -> Result<(), String>` — enigo keystroke: release Super/Control/Shift/Alt,
    then press+release `V` with the primary modifier held (Cmd on macOS, Ctrl elsewhere).
    Releasing modifiers first prevents the still-held hotkey from turning the paste into
    e.g. Cmd+Shift+V.
- Wired only in `shortcut::run_shortcut_upload` (`src-tauri/src/shortcut/mod.rs`): capture
  the upload result and call `paste::paste_after_delay()` when `should_paste` says so.
  `commands::trigger_upload_now` (tray menu) and the settings UI are untouched.
- Dependency: `enigo` added to `src-tauri/Cargo.toml` (`cargo add enigo`, pin the resolved
  0.x version).

### 2.4 Failure handling and notifications

- Paste failure never affects the upload: the path stays in the clipboard and one new
  notification is shown: `Message::PasteFailed` → *"Path copied, but auto-paste failed —
  paste it manually. macOS: grant Clipship the Accessibility permission (System Settings →
  Privacy & Security → Accessibility)."* On non-macOS the hint is replaced by a generic
  note (the desktop session / compositor may block synthetic input). Same
  platform-conditional rendering pattern as `Message::SshBinariesMissing`.
- On macOS, synthetic keystrokes can also be silently dropped when the permission is
  missing (CGEvent posts without an error). This cannot be fully detected; the settings
  description and README carry the permission note, and the failure notification covers
  the detectable cases.

### 2.5 Platform matrix

| Platform | Keystroke | Permission | Degradation |
|----------|-----------|------------|-------------|
| macOS | Cmd+V | Accessibility (grant once) | notification (detectable errors) + documented hint |
| Windows | Ctrl+V | none | notification |
| Linux X11 | Ctrl+V | none | notification |
| Linux Wayland | Ctrl+V | compositor-dependent | notification; path stays in clipboard |

## 3. Testing

- **Rust** (`cargo test` in `src-tauri/`):
  - config: `auto_paste` defaults to false when the field is absent; round-trips through
    save/load (mirroring the `shortcut_double_tap` tests).
  - `paste::should_paste` truth table: off+success → false; on+`clipboard_updated: true` →
    true; on+`clipboard_updated: false` → false; on+error → false.
  - existing suites keep passing unchanged.
- **Frontend**: `pnpm check` (svelte-check) and `pnpm test` (vitest) stay green.
- **Visual/manual**:
  - `pnpm tauri icon public/app-icon.svg` output lands in `src-tauri/icons/`; Dock and
    installer icons show Fileport, not the Tauri logo.
  - macOS menu bar: glyph is monochrome and inverts with the menu-bar theme; Windows hover
    tooltip reads `Clipship`.
  - Toggle on + hotkey in a text field → the path is pasted; toggle off → only the
    clipboard is updated; SSH mid-upload clipboard change → no paste.
